----------------------------------------------------------lexical environment----------------------------------------------------------------------------------

lexical environment - it is component of execution context
                    - refer to environment where varaiables and functions are defined in relation to their execution scope, structured accordingly during creation phase
                    - it consist of two primary components:
                      1. Environment Record: This is where variable and function declarations from the current execution scope
                      2. Reference to the Outer Lexical Environment: Each lexical environment keeps a reference to its outer (parent) lexical environment, forming a "scope chain."

scope chaining -  lexical environment consist of a reference to the outer or parent execution scope until the global scope creating a scope chain

Scope chaining in JavaScript refers to the way in which the scope of variables is determined through a chain of lexical environments, starting from the current scope and moving outward through its parent scopes, until it reaches the global scope.

------------------------------------------------------ASYNC--------------------------------------------------------------------------------------
https://javascript.info/promise-basics


- Javascript engine single treaded and has single stack, executing one execution context top to bottom at a time.
- so whenever the functions needs to work with timetaking outside environment it is handled Asyncronously without non-blocking the other js execution for other tasks
-  Asyncronously APIs regester the ASync function as a callBack and waits for work to be done after the the regestered callback is pushed to the callBack queue.
- when that api task is done the callBack function gets queued inside a callBack queue, where two queue that are prority queue and callBack queue
- between callBack queue and call stack there is mechanism call Event loop which constantly moniters callstack and queue, checking for the call stack to be empty and pushing the callBacks.
- API enclosed callbacks enter callback queue, the other enclose callbacks like then/catch will be in priority queue because those time taken is already done

- in case of callback ASYNC APIs encloses the CB function code where as in promises the created promise object has the CB code and the APIs sperately
- Callbacks → The API encloses the callback function inside its implementation.
- Promises → The API and the callback function (which is executed when resolved) are separate, and the promise object holds the execution logic.



Promise: Promise is an object that represents the eventual completion or failure of Async operation and its resulting value.
         - it helps manage Async code more efficiently avoiding callBack Hell and Inversion of control.
         - what happens behind is:
           - when create a new promise a promise object is created having: state, Result, then etc properties
           - while creating a promise we would have given is an executer function enclosing a API having access to resolve and reject methods
           - after the APIs works API call either of the methods according 
           - the Methods with the data/error goes execution stack via callback queue which upon executing invokes the attached then CB function passing the resolved data
           - after resolve action then releses the function to the microtask queue and then to the callstack job is done and that then function always returns a promise enabling promise chaining.


ASYNC/AWAIT:  Async is attached to the function enabling easy to write Asyncronous code inside like writing promise chaining in a syncronous manner using Await
            - Await is used to wait for the promises to resolve and return a value
            - in callstack the js engine reads like a normal function, until stumbles upon await , if the promise is not yet resolves the execution stops and the function is looped via microtask queue until resolved and the execution starts from there
            - await is wait fior the promise call resolve and Promise then functionality is done like nornal flow.
